# 已知问题与反思

## 已知问题

- OpenClaw CLI 调用真实模型时可能受网络、模型响应速度和 Gateway 状态影响，单轮生成会比本地演示模式慢。
- OpenClaw Agent 本身带有个人助手系统提示，因此角色扮演依赖强约束 Prompt，不能保证每次都完全一致。
- 当前 Demo 没有保存历史会话到数据库，刷新页面后需要重新导出或重新生成。
- 本地演示模式只是兜底逻辑，不能代表真实模型质量。

## 风险控制

- 最大轮数硬限制为 6，前端和后端都做了限制。
- 用户可以随时点击停止。
- OpenClaw 异常会返回 fallback，不会无限等待。
- API Key 只由 OpenClaw 本地配置管理，本项目不读取或展示密钥。

## 后续改进

- 接入 OpenClaw HTTP Chat Completions endpoint，减少 CLI 启动开销。
- 为每个角色建立独立 agent 或独立 session，降低主助手人格干扰。
- 增加截图自动生成脚本，方便提交作业。
- 增加对话质量评分，例如“是否重复”“是否越界”“是否引用了未给资料”。

## 反思

这个作业的关键不是让两个 AI 无限聊天，而是把自动化边界设计清楚。角色目标、资料权限、禁止事项和停止条件比界面本身更重要。Demo 采用“单轮请求 + 前端调度”的设计，是为了让停止按钮真正有效，也方便展示每一轮如何被控制。
