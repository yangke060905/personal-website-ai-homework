## 1. 项目背景

本加分题要求使用 OpenClaw 做一个双角色聊天 APP。它不是普通的单角色问答，也不是用户持续输入驱动的聊天，而是让两个预设角色按照各自身份、目标、资料权限和禁止事项自动互相发送消息。

作业的核心难点有三个：

1. 双角色必须能形成闭环，而不是只有一个助手回复用户。
2. 角色必须有边界，不能随意编造、越权或无限扩展话题。
3. 对话必须能停止，不能出现无限循环。

因此，本项目设计为一个“有限轮次角色协商控制台”：用户在同一页面配置两个角色、导入资料、设置最大轮数和停止词，然后启动 A/B 自动对话，并导出 Markdown 或 JSON 作为运行证据。

## 2. 产品目标

### 2.1 业务目标

- 完成一个可运行的 OpenClaw 双角色聊天 Demo。
- 满足课程加分题对角色定义、自动对话、停止机制和提交材料的要求。
- 让老师可以通过截图、导出记录和文档快速判断项目完整度。

### 2.2 用户目标

- 用户可以快速选择一组角色模板。
- 用户可以看清每个角色的身份、目标、可用资料和禁止事项。
- 用户可以一键启动双角色自动对话。
- 用户可以随时停止对话。
- 用户可以导出便于阅读的 Markdown 作业记录。

### 2.3 设计目标

- 首屏直接是可操作 Demo，不做营销页。
- 角色边界和停止机制必须显性展示。
- 运行状态必须清楚，不能让用户误以为卡死。
- OpenClaw 真实生成和本地示例脚本必须明确区分。

## 3. 用户画像与使用场景

### 3.1 主要用户

| 用户 | 需求 |
| --- | --- |
| 学生/提交者 | 快速完成加分题 Demo，保留运行截图和导出文件 |
| 老师/评审者 | 快速确认项目是否满足双角色、边界、停止和文档要求 |
| 演示者 | 课堂上稳定展示流程，即使模型响应慢也能说明异常处理 |

### 3.2 典型场景

#### 场景 A：课堂现场展示

用户打开本地页面，选择“产品经理 × 风险官”，点击开始，让两个角色围绕一个 AI 功能是否上线进行有限轮次讨论。展示结束后导出 Markdown。

#### 场景 B：提交作业材料

用户将项目代码、PRD、设计说明、已知问题、截图和导出记录打包提交。

#### 场景 C：OpenClaw 响应慢

用户选择 OpenClaw 真实生成。如果 OpenClaw 超时，系统显示错误并停止，证明项目具备异常停止机制；用户可切换到本地示例脚本展示 UI 流程。

## 5. 核心功能需求

### 5.1 角色模板

系统提供三组模板：

| 模板 | 适用场景 |
| --- | --- |
| 产品经理 × 风险官 | 产品上线评审、功能边界讨论 |
| 金融顾问 × 谨慎客户 | 投资风险解释、保守决策 |
| 研究员 × 事实核查员 | 研究结论校验、证据边界检查 |

用户切换模板时，系统自动填充讨论主题、资料背景、角色目标和边界。

### 5.2 角色定义

每个角色必须具备以下字段：

| 字段 | 说明 |
| --- | --- |
| 身份 | 角色名称，例如产品经理、风险官 |
| 目标 | 本角色在对话中要达成什么 |
| 可用资料 | 本角色允许使用的信息来源 |
| 禁止事项 | 本角色不能做什么 |
| 结束条件 | 什么时候应该主动收束 |

### 5.3 资料导入

用户可以为全局资料或单个角色导入文本文件。

支持格式：

- `.txt`
- `.md`
- `.csv`
- `.json`
- `.log`

限制：

- 单文件最大 1MB。
- 文件内容以 UTF-8 文本读取。
- 导入后追加到对应资料框，不覆盖原有内容。

### 5.4 自动对话

用户点击“开始自动对话”后，系统按以下规则执行：

1. A 角色生成第 1 句。
2. B 角色读取已有上下文并生成第 2 句。
3. A/B 继续交替。
4. 达到停止条件后结束。

每轮请求都会携带：

- 讨论主题
- 全局资料
- 当前角色定义
- 对方角色摘要
- 已有对话记录
- 最大轮数
- 停止词

### 5.5 OpenClaw 真实生成

后端通过 OpenClaw CLI 调用：

```powershell
openclaw agent --agent main --session-key <conversation> --message-file <prompt> --thinking off --timeout 45 --json
```

模型必须返回：

```json
{
  "message": "角色发言",
  "shouldStop": false,
  "stopReason": ""
}
```

如果 OpenClaw 超时、返回空值或返回格式不可解析，系统显示错误并停止，不使用模板内容冒充模型回答。

### 5.6 本地示例脚本

本地示例脚本用于演示 UI 流程和停止机制。该模式必须明确标注为 `local-demo-script`，不得在报告中声称是 OpenClaw 真实生成。

### 5.7 停止机制

系统支持四类停止：

| 停止方式 | 说明 |
| --- | --- |
| 最大轮数 | 最大不超过 6 |
| 停止词 | 命中用户设置的停止词 |
| 角色自判 | 模型返回 `shouldStop=true` |
| 人工停止 | 用户点击停止按钮 |
| 异常停止 | OpenClaw 超时或出错 |

默认停止词：

```text
[结束],[停止],DONE,同意收束
```

停止词采用保守匹配，避免普通句子里的“人工停止入口”误触发。

### 5.8 导出

系统支持两种导出：

| 导出格式 | 用途 |
| --- | --- |
| Markdown | 给老师阅读、提交作业、保留过程 |
| JSON | 保留完整结构化数据和 provider 信息 |

Markdown 导出包含：

- 导出时间
- 模型通道
- 最大轮数
- 停止词
- 停止状态
- 讨论主题
- 可用资料
- 角色定义
- 对话记录
- 控制机制说明

## 6. 页面与交互设计

### 6.1 页面结构

页面分为三块：

1. 左侧运行控制区
   - 模板选择
   - 主题与资料
   - 最大轮数
   - 模型通道
   - 停止词
   - 开始/停止按钮

2. 中部角色配置区
   - 角色 A
   - 角色 B
   - 各自目标、资料、禁止事项、结束条件

3. 下方对话记录区
   - 对话气泡
   - 角色标识
   - 轮次
   - provider
   - 导出按钮
   - 停止提示

### 6.2 关键交互

- 点击开始后立即出现“生成中”气泡。
- 每轮完成后替换为实际结果。
- OpenClaw 失败时将 pending 气泡替换为错误信息。
- 点击停止后立即中断后续轮次。
- 导入资料后自动追加到资料框。
- 导出 Markdown 时加 UTF-8 BOM，降低 Windows 打开乱码概率。

```json

  "turnIndex": 1,

}
```

## 8. 异常处理

| 异常 | 处理 |
| --- | --- |
| OpenClaw CLI 不存在 | 健康检查显示不可用 |
| OpenClaw 超时 | 当前轮失败并停止 |
| 返回空值 | 当前轮失败并停止 |
| JSON 不可解析 | 当前轮失败并停止 |
| 用户点击停止 | 中断后续循环 |
| 文件过大 | 提示用户先整理摘要 |

## 12. 已知问题与后续优化

### 12.1 已知问题

- OpenClaw/DeepSeek 在本机偶尔响应较慢，可能触发超时。
- 当前没有数据库，刷新页面会清空未导出的记录。
- 文件导入目前只支持文本类文件，不支持 PDF/Word 解析。

### 12.2 后续优化

- 接入 OpenClaw HTTP Chat Completions endpoint，减少 CLI 启动开销。
- 为两个角色配置独立 agent，进一步降低主助手人格干扰。
- 增加 PDF/Word 文件解析。
- 增加对话质量检查，例如重复检测、越界检测、资料引用检查。
